# StreetVulkan Web Client (`web`)

## Overview

The `web` package implements the browser-based 3D street renderer (`streetvulkan-web`) for StreetVulkan. An HTML document shell (`index.html`) loads `app.js` as an ES module, which streams GLB 2.0 sector geometry, chunk bounding boxes, texture atlases, and optional traffic signal coordinates, falling back to procedural assets and a standalone Rolcar plaza sector if remote data is unavailable.

Per-frame camera kinematics, projection and view matrices, Gribb/Hartmann frustum extraction, chunk AABB culling, and 24-second traffic signal cycling run inside WebAssembly linear memory via `street_vulkan_core.wasm`. Per `../Makefile.wasm`, `street_vulkan_core.wasm` is the assembled output of `street_vulkan_core.wat` (or can be compiled from `main_wasm.c` and `src/math_camera.c` with Emscripten). Rendering executes through `WebGPURenderer` (`shaders.wgsl`) with automatic fallback (or `?backend=webgl2` override) to `WebGL2Renderer` using embedded GLSL ES 3.00 shaders (`VS_GLSL300` and `FS_GLSL300`).

## Invariants

- `[package.json:type]`, `[index.html:#viewport]`: Browser runtime must load scripts with `"type": "module"`. Canvas fills `100vw` x `100vh` with `touch-action: none`; `[index.html:.hud-panel]` and `[index.html:.controls-hint]` keep `pointer-events: none`, and `[index.html:#loader-overlay]` disables pointer interception when `.hidden` is applied.
- `[app.js:loadStreetVulkanWasm]`, `[main_wasm.c:get_version]`, `[street_vulkan_core.wat:get_version]`: WASM ABI version check requires `get_version()` to return `1`; any other return value throws an error.
- `[app.js:MEM_POS_PTR]`, `[street_vulkan_core.wat:memory]`: Linear memory is fixed at 2 WASM pages (131,072 bytes) with zero internal static allocations; `app.js` creates `f32Mem` and `u8Mem` views once after instantiation and requires non-growing memory with static pointer offsets (`MEM_POS_PTR=0x0004`, reserving `0x0000..0x0003` as a NULL guard, and `MEM_AABBS_PTR=0x0200` spanning `24,576` bytes for `MAX_CULL_BATCH=1024` 6-float AABBs before `MEM_FLAGS_PTR=0x8000`).
- `[main_wasm.c:camera_get_vectors]`, `[main_wasm.c:cull_chunks]`, `[street_vulkan_core.wat:camera_get_vectors]`, `[street_vulkan_core.wat:camera_step]`, `[street_vulkan_core.wat:mat4_multiply]`, `[main_wasm.c:mat4_multiply]`: C exports guard against `NULL` pointers (and `count <= 0` in `cull_chunks`), whereas WAT `camera_get_vectors` skips an output pointer only when `ptr < 0` (address `0` is valid) and other WAT functions trap on out-of-bounds memory without null checks; `app.js` passes non-zero `MEM_POS_PTR=0x0004` so C `if (!pos) return;` guards work if compiled from `main_wasm.c`. Both `mat4_multiply` implementations buffer inputs in locals before writing `out_ptr`, preserving aliasing safety.
- `[street_vulkan_core.wat:$trig_f64]`, `[street_vulkan_core.wat:$tan_f32]`: `NaN` inputs short-circuit before `i32.trunc_f64_s`, and `|x| >= 1000000.0` triggers coarse `2*pi` reduction prior to Cody-Waite reduction and degree-11/12 Taylor evaluation.
- `[main_wasm.c:mat4_perspective_webgpu]`, `[main_wasm.c:mat4_perspective_webgl]`, `[street_vulkan_core.wat:mat4_perspective_webgpu]`, `[street_vulkan_core.wat:mat4_perspective_webgl]`, `[street_vulkan_core.wat:mat4_lookat]`, `[street_vulkan_core.wat:frustum_extract]`, `[street_vulkan_core.wat:cull_chunks]`, `[app.js:main]`: Matrices are column-major right-handed (`+Y` up), with `Z` in `[0, 1]` for WebGPU and `[-1, 1]` for WebGL. `app.js` fixes perspective `fovy=60.0` deg, `near=1.0`, `far=15000.0`, clamps DPR to `<= 2`, pitch to `[-89.0, 89.0]` deg, and `dt` to `[0.0001, 0.1]` s, and always extracts frustum planes from `MEM_MVP_WGPU_PTR` (even under WebGL2) because `frustum_extract` uses the `0 <= z <= w` Gribb/Hartmann plane order (`Left`, `Right`, `Bottom`, `Top`, `Near`, `Far`) before `cull_chunks` tests packed 24-byte AABBs (`min_x, min_y, min_z, max_x, max_y, max_z`).
- `[main_wasm.c:traffic_tick]`, `[street_vulkan_core.wat:traffic_tick]`, `[app.js:loadOptionalTrafficSignals]`, `[app.js:main]`: Traffic simulation wraps `*sim_time_ptr` to `[0.0, 24.0)` with phases `0` (`[0, 9)` NS Green), `1` (`[9, 12)` NS Amber), `2` (`[12, 21)` EW Green), and `3` (`[21, 24)` EW Amber). Loaded traffic signals are filtered to `-128 <= x <= 1152` and `-128 <= z <= 1152`. Dynamic lights cap at `64` total (`<= 48` traffic lights within `450m` at `radius=22.0`, `intensity=3.8`, plus 1 Rolcar storefront light at `(969.0, 6.5, 779.0)` with `radius=35.0`, `intensity=3.2 * nightStrength` when `nightStrength > 0.05`).
- `[app.js:parseGLB]`, `[app.js:extractAccessorTypedArray]`, `[app.js:resolveSectorManifest]`, `[app.js:main]`: `parseGLB` requires byte length `>= 20`, little-endian magic `0x46546C67`, `version=2`, JSON chunk `0x4E4F534A` with non-empty `meshes`, non-zero BIN chunk `0x004E4942`, and `POSITION` on `meshes[0].primitives[0]`; `indexFormat` is `'uint16'` only when `componentType === 5123`, and missing `NORMAL`/`TEXCOORD_0`/`COLOR_0`/`_EMISSION` synthesize defaults (`[0,1,0]`, `[0,0]`, `[1,1,1,1]`, `0`). `extractAccessorTypedArray` uses zero-copy typed views only for tightly packed, element-aligned accessors. Background streaming runs only when `sectorCache.size < 4`, `loadingSectors.size === 0`, sector center distance `< 1500.0`, and `vert_count >= 100`.
- `[renderer_webgpu.js:WebGPURenderer.init]`, `[renderer_webgpu.js:WebGPURenderer.uploadSector]`, `[renderer_webgl2.js:WebGL2Renderer.init]`, `[renderer_webgl2.js:WebGL2Renderer.uploadSector]`, `[shaders.wgsl:VertexInput]`, `[shaders.wgsl:Uniforms]`, `[renderer_webgl2.js:VS_GLSL300]`, `[renderer_webgl2.js:FS_GLSL300]`: Both renderers expect 5 separate unnormalized `float32` vertex attributes at locations `0..4` (`pos` 12B, `norm` 12B, `uv` 8B, `col` 16B where `.a` carries `matID`, `em` 4B), a 2272-byte uniform block (`mvp`, `model`, `sunDir`, `skyColor`, `camPos`, `flashPos`, `flashDir`, `params`, `lights[64]`), bindings at uniform `0`, `satelliteTex` (`TEXTURE0` / `@binding(2)`), `facadeTex` (`TEXTURE1` / `@binding(3)`), triangle-list topology, CCW front faces, no backface culling, `less-equal` depth test/write, and `SRC_ALPHA`/`ONE_MINUS_SRC_ALPHA` color blending.
- `[renderer_webgpu.js:WebGPURenderer.render]`, `[renderer_webgpu.js:WebGPURenderer._createGpuBuffer]`, `[renderer_webgpu.js:WebGPURenderer._createRgbaTexture]`, `[renderer_webgl2.js:WebGL2Renderer.render]`, `[renderer_webgl2.js:WebGL2Renderer._createGlTexture]`, `[shaders.wgsl:fs_main]`: Chunk `i` draws iff `sec.chunks.length === 0` or `!frame.cullingEnabled || !flags || flags[i] !== 0`. WebGPU pads buffers to 4-byte multiples, returns zeroed stats before `uploadTextures()` creates `bindGroup`, resizes its explicit `depth24plus` texture on canvas dimension mismatch, and uploads single-level `rgba8unorm` textures without mipmap generation, whereas WebGL2 generates full mipmaps (`generateMipmap`) and multiplies `chk.start` by `sec.indexBytes`. Both fragment shaders select shading paths by `emission >= 9.5` and `matID = color.a` ranges, modulate high-emission (`emission >= 4.0`) surfaces via `params.z` / `u_params.z` (`timeSec`), and keep `NdotL >= 0.35` for point lights on non-vertical surfaces (`abs(N.y) > 0.35`).

## Side Effects

- `[app.js:main]`: Auto-invokes `main()` at module load, attaches window/canvas/button event listeners, requests pointer lock on canvas click, mutates `canvas.width`/`canvas.height`, updates loader, telemetry HUD, and toast DOM elements every `0.25s` and on input, writes WASM linear memory (`f32Mem[(MEM_POS_PTR >> 2)..(MEM_POS_PTR >> 2) + 2]`, `MEM_SIM_TIME_PTR`, `MEM_AABBS_PTR`), runs a continuous `requestAnimationFrame` loop, and logs warnings/errors to `console`.
- `[app.js:loadStreetVulkanWasm]`, `[app.js:loadTextureAtlasWithFallback]`, `[app.js:resolveSectorManifest]`, `[app.js:fetchChunksForSector]`, `[app.js:fetchArrayBufferWithProgress]`, `[app.js:loadOptionalTrafficSignals]`, `[renderer_webgpu.js:WebGPURenderer.init]`: Issue HTTP `GET`/`HEAD` requests for `./street_vulkan_core.wasm`, `./shaders.wgsl`, `texture_atlas_16x16.png`, `sectors.json`, `sector_0_0.glb`, `chunks_*.json`, `sector_*.glb`, and `traffic_signals.json`; `loadTextureAtlasWithFallback` allocates an offscreen 2D `<canvas>`, reads `getImageData()`, and calls `bmp.close?.()`.
- `[main_wasm.c:camera_step]`, `[main_wasm.c:camera_get_vectors]`, `[main_wasm.c:mat4_perspective_webgpu]`, `[main_wasm.c:mat4_perspective_webgl]`, `[main_wasm.c:mat4_lookat]`, `[main_wasm.c:mat4_multiply]`, `[main_wasm.c:frustum_extract]`, `[main_wasm.c:cull_chunks]`, `[main_wasm.c:traffic_tick]`, `[street_vulkan_core.wat:camera_step]`, `[street_vulkan_core.wat:camera_get_vectors]`, `[street_vulkan_core.wat:mat4_perspective_webgpu]`, `[street_vulkan_core.wat:mat4_perspective_webgl]`, `[street_vulkan_core.wat:mat4_lookat]`, `[street_vulkan_core.wat:mat4_multiply]`, `[street_vulkan_core.wat:frustum_extract]`, `[street_vulkan_core.wat:cull_chunks]`, `[street_vulkan_core.wat:traffic_tick]`: Overwrite caller-provided byte ranges in WASM linear memory in place (`12` bytes per `vec3`, `64` bytes per `mat4`, `96` bytes for frustum planes, `count` bytes for cull flags, `4` bytes for `sim_time`).
- `[renderer_webgpu.js:WebGPURenderer]`, `[renderer_webgl2.js:WebGL2Renderer]`, `[shaders.wgsl:fs_main]`, `[renderer_webgl2.js:FS_GLSL300]`: Acquire WebGPU device/swapchain or WebGL2 context, mutate global WebGL state, compile/link shaders, allocate, replace, and destroy GPU textures, depth textures, UBO/uniform buffers, VAOs, and sector vertex/index buffers, update `this.sectors`, discard transparent alpha-tested facade fragments (`0.98 <= matID <= 1.02`, `emission < 0.1`, `fac.a < 0.25`, `color.rgb > 0.92`), and submit GPU render commands to the canvas each frame.
